# 模块8 · AI × 数据开发（Data Agent / RAG）

> [!info] 本模块目标
> 不是学「怎么调大模型」，而是学**怎么让模型在真实数仓上取对数**。真正的难点从来不是生成 SQL，而是 Schema 太大、口径说不清、结果没法验证。所以本模块的重心是：语义层、检索、评测、权限与审计。

## 核心问题（学完必须能答）

1. 为什么「把整个 DDL 塞进 Prompt」在真实数仓里必然失败？有哪三种替代方案？
2. Text2SQL 的「执行准确率」和「结果正确率」差在哪？为什么前者容易虚高？
3. 模型生成的 SQL 语法正确但口径错了，你怎么在系统层面拦住？
4. RAG 里「历史 SQL 对」为什么比「表结构文档」更有用？怎么组织它们？
5. Agent 执行 SQL 报错后自动重试，什么时候会陷入死循环？怎么设计终止条件？
6. 怎么把「只有这个部门能看这几行」的权限，安全地透传到 Agent 生成的 SQL 上？
